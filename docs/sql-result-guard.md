# SQL 结果内存保护

本配置会在查询结果超过预算时停止接收，丢弃本次不完整结果，并保留上一份成功显示的表格。自动保护覆盖 MySQL 输出接收，以及 Grip 的结果复制、渲染、编辑和导入入口。

修改配置后新开或重启 Neovim 生效。已有 Neovim 实例不会自动热替换正在使用的回调链。

## 默认预算

配置入口：`lua/config/dadbod-grip.lua` 中的 `config.sql-result-guard.install({...})`。

| 配置项 | 默认值 | 计量方式 |
| --- | ---: | --- |
| `max_rows` | 10,000 | 数据行，表头不算；暂存插入也占行数 |
| `max_cells` | 200,000 | 全部数据行 × 全部列，隐藏列也算 |
| `max_columns` | 256 | 全部列 |
| `max_bytes` | 16 MiB | 接收阶段计原始 stdout；状态阶段计列名、原始值和暂存值 |
| `max_stderr_bytes` | 64 KiB | 最多保留的客户端错误输出 |

等于上限允许通过；严格超过任一项就拒绝。没有“只保留前面一部分”的隐式截断，也不会把截断结果显示成完整查询。

自动列宽最多 40 个显示字符。原有手动调宽仍可使用，上限保持 200；数据库中的完整单元格值不会因为显示截断而被改写。

16 MiB 是数据预算，不是整个 Neovim 进程的 RSS 上限。Lua 表、渲染文本、标记、撤销历史以及其他插件还会占内存。

## 使用方式

`<Space>sr` 继续严格执行原 SQL，不自动追加 LIMIT。在预算内显示完整结果，排序仍在本地完成。超过预算时，应缩小时间范围、修正连接条件，或在 SQL 中显式指定需要的 LIMIT。

`<Space>st` 打开表仍按 `LIMIT 1000` 加载；排序、筛选和翻页保持原数据库重查逻辑。不会为了这套保护额外执行 COUNT 或 EXPLAIN。

例如超过行数上限会提示：

```text
结果超出保护阈值：数据行数已达到 10001，上限 10000。
```

接收中可用 `Ctrl-C` 取消；命令接口为 `:SQLCancel`。取消、超限、客户端报错和超时都不发布部分结果。关闭相关窗口会取消该次结果接收；新查询取代仍在等待的旧查询时，旧结果不能覆盖新结果。

保留内容包括旧结果数据、SQL、筛选、排序、分页信息和撤销栈。拒绝大单元格编辑或批量插入时，不会先写入新的撤销记录。数据库写操作仍由原有编辑确认流程负责；停止接收不代表撤销数据库已经执行的操作。

## 导入保护

`GripImport` 的剪贴板和 pipe 导入也有预算。原始文本先检查字节数和结构，再进入原解析器；解析后的数据还要与当前表格一起检查总行数、单元格和暂存值大小。

CSV/TSV 预检理解双引号、转义双引号、引号内换行和 CRLF。为限制解析器实际创建的表，随后可能被过滤掉的空记录仍占“待解析记录”预算。

JSON 预检只扫描结构，不创建完整解码树；最多允许 64 层嵌套，并限制嵌套容器数量。完整语法仍由原 JSON 解析器校验。小型合法导入仍先按原流程确认，再进入暂存区。

剪贴板内容必须先从系统剪贴板取得，因此不能保证取得原始字符串这一步完全不分配内存。pipe 输出会边接收边检查字节预算。

## 实现位置与边界

| 文件 | 职责 |
| --- | --- |
| `lua/config/sql-result-budget.lua` | 统一预算、状态计量、导入预检 |
| `lua/config/sql-result-stream.lua` | MySQL/pipe 输出接收、分块计数、取消与清理 |
| `lua/config/sql-result-guard.lua` | 查询作用域、状态回滚、复制/渲染/编辑入口保护 |
| `lua/config/sql-credentials/grip.lua` | 保留现有取密流程，在客户端启动边界接入接收器 |
| `lua/config/sql-runner.lua`、`sql-browser.lua` | 完整查询与本地排序回调共享结果代次 |

MySQL 结果查询通过 `--quick` 逐行读取。请求标记在进入等待循环前消费，普通元数据命令不会误继承上一次接收预算。原始 SQL、连接模板和凭据获取方式保持原流程。

其他数据库已有结果复制/渲染预检，但还没有各自的流式协议接收器；不能据此宣称它们的原始输出接收内存也受 16 MiB 限制。

取消会停止本地结果读取，并对该次启动的客户端发送终止信号。超限时不保证数据库服务端立刻结束原查询；复杂连接、扫描和服务端排序仍应单独优化。没有使用自动 COUNT、自动重跑或虚拟滚动。

全部兼容代码放在本配置仓库，未修改 `lazy/dadbod-grip.nvim` 安装目录。升级 Grip 后若相关接口变化，安装断言会要求更新兼容层，回归测试也应重新运行。

## 验证

在配置仓库根目录执行，要求已安装 Dadbod Grip；也可用 `DADBOD_GRIP_DIR` 指定插件目录：

```sh
nvim --headless -u NONE -i NONE -l tests/sql-result-budget.lua
nvim --headless -u NONE -i NONE -l tests/sql-result-stream.lua
nvim --headless -u NONE -i NONE -l tests/sql-result-credentials.lua
nvim --headless -u NONE -i NONE -l tests/sql-result-guard.lua
```

前四个套件不连接真实数据库。流测试只启动可控的合成客户端，覆盖边界、单字节分块、超长单行、取消、超时及迟到回调。集成测试加载真实 Grip，检查失败前不复制/渲染、旧结果和元数据保留、编辑/导入、本地排序、新旧查询竞争和结果引用释放。

可选真实 MySQL 冒烟只执行 4 条常量 SELECT，不读取业务表或写入数据。需在具备已有连接环境和系统凭据服务的终端中显式指定连接名：

```sh
SQL_GUARD_TEST_CONNECTION=platform_st_test nvim --headless -u NONE -i NONE -l tests/sql-result-guard-live.lua
```

此测试将自己的预算临时设为 3 行、6 格、2 列和 256 字节，验证普通查询、行数超限、字节数超限，以及超限后的下一次正常查询。它不会修改正式配置的默认预算。
